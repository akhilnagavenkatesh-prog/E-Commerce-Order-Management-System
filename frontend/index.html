DDL: Data Definition Language

Defines the database schema, entity structures, constraints, primary keys, and foreign keys.

1. CREATE TABLE CUSTOMER 
CREATE TABLE CUSTOMER (
    Customer_ID   VARCHAR(20)  PRIMARY KEY,
    Customer_Name VARCHAR(100) NOT NULL,
    Email         VARCHAR(100) UNIQUE NOT NULL,
    Phone         VARCHAR(20)  NOT NULL,
    Address       VARCHAR(255) NOT NULL
);
2. CREATE TABLE PRODUCT 
CREATE TABLE PRODUCT (
    Product_ID   VARCHAR(20)   PRIMARY KEY,
    Product_Name VARCHAR(150)  NOT NULL,
    Category     VARCHAR(50)   NOT NULL,
    Price        DECIMAL(10,2) NOT NULL CHECK (Price > 0),
    Stock        INT           NOT NULL DEFAULT 0
);
3. CREATE TABLE ORDERS 
CREATE TABLE ORDERS (
    Order_ID     VARCHAR(20)   PRIMARY KEY,
    Customer_ID  VARCHAR(20)   NOT NULL,
    Order_Date   DATE          NOT NULL,
    Total_Amount DECIMAL(10,2) NOT NULL DEFAULT 0.00,
    Status       VARCHAR(30)   DEFAULT 'Pending',
    FOREIGN KEY (Customer_ID) 
        REFERENCES CUSTOMER(Customer_ID) 
        ON DELETE RESTRICT ON UPDATE CASCADE
);
4. CREATE TABLE ORDER_ITEM 
CREATE TABLE ORDER_ITEM (
    Order_Item_ID VARCHAR(20)   PRIMARY KEY,
    Order_ID      VARCHAR(20)   NOT NULL,
    Product_ID    VARCHAR(20)   NOT NULL,
    Quantity      INT           NOT NULL CHECK (Quantity > 0),
    Price         DECIMAL(10,2) NOT NULL,
    FOREIGN KEY (Order_ID) 
        REFERENCES ORDERS(Order_ID) 
        ON DELETE CASCADE ON UPDATE CASCADE,
    FOREIGN KEY (Product_ID) 
        REFERENCES PRODUCT(Product_ID) 
        ON DELETE RESTRICT ON UPDATE CASCADE
);
5. ALTER & DROP Operations 
-- ALTER TABLE: Add index for faster query lookup on Customer orders
ALTER TABLE ORDERS ADD INDEX idx_orders_customer (Customer_ID);

-- ALTER TABLE: Add CHECK constraint on Order Status values
ALTER TABLE ORDERS ADD CONSTRAINT chk_order_status 
CHECK (Status IN ('Pending', 'Processing', 'Shipped', 'Delivered', 'Cancelled'));

-- DROP TABLE: Drop dependent bridge table first to avoid FK constraint error
DROP TABLE IF EXISTS ORDER_ITEM;
DROP TABLE IF EXISTS ORDERS;
DROP TABLE IF EXISTS PRODUCT;
DROP TABLE IF EXISTS CUSTOMER;

DELETE Operations (Referential Integrity Check) 
-- 1. Delete an order item
DELETE FROM ORDER_ITEM 
WHERE Order_Item_ID = 'ITEM-409';

-- 2. Delete an entire order (Cascades to child ORDER_ITEM rows via ON DELETE CASCADE)
DELETE FROM ORDERS 
WHERE Order_ID = 'ORD-306';

DQL: Data Query Language

Retrieval, filtering, sorting, and aggregate analytics over e-commerce entity tables.

1. Standard Table Selections 
-- Retrieve all customers
SELECT * FROM CUSTOMER;

-- Retrieve all products
SELECT * FROM PRODUCT;

-- Retrieve all orders
SELECT * FROM ORDERS;

-- Retrieve all order items
SELECT * FROM ORDER_ITEM;
2. Filtered & Sorted Queries 
-- Filter low-stock products sorted by price descending
SELECT Product_ID, Product_Name, Category, Price, Stock
FROM PRODUCT
WHERE Stock < 20
ORDER BY Price DESC;

-- Find pending or processing orders above $200
SELECT Order_ID, Customer_ID, Order_Date, Total_Amount, Status
FROM ORDERS
WHERE Status IN ('Pending', 'Processing') 
  AND Total_Amount > 200.00;
3. Aggregations (GROUP BY & HAVING) 
-- Count orders & calculate total revenue by status
SELECT 
    Status, 
    COUNT(*) AS Total_Orders, 
    SUM(Total_Amount) AS Total_Revenue,
    AVG(Total_Amount) AS Average_Order_Value
FROM ORDERS
GROUP BY Status;

-- Group products by category and filter categories with high total stock
SELECT 
    Category, 
    COUNT(*) AS Product_Count, 
    SUM(Stock) AS Total_Stock,
    ROUND(AVG(Price), 2) AS Avg_Price
FROM PRODUCT
GROUP BY Category
HAVING Total_Stock > 25
ORDER BY Total_Stock DESC;

Relational JOIN Operations

Demonstrating how entities link together: CUSTOMER → ORDERS → ORDER_ITEM → PRODUCT.

1. INNER JOIN (ORDERS & CUSTOMER) 
SELECT 
    O.Order_ID,
    C.Customer_Name,
    C.Email,
    O.Order_Date,
    O.Total_Amount,
    O.Status
FROM ORDERS O
JOIN CUSTOMER C 
  ON O.Customer_ID = C.Customer_ID
ORDER BY O.Order_Date DESC;
2. ORDER_ITEM & PRODUCT JOIN 
SELECT 
    OI.Order_Item_ID,
    OI.Order_ID,
    P.Product_Name,
    P.Category,
    OI.Quantity,
    OI.Price AS Unit_Price,
    (OI.Quantity * OI.Price) AS Subtotal
FROM ORDER_ITEM OI
JOIN PRODUCT P 
  ON OI.Product_ID = P.Product_ID;
3. Complete 4-Entity Relational JOIN 
-- Full traversal across all 4 database tables
SELECT 
    O.Order_ID,
    C.Customer_Name,
    C.Phone,
    P.Product_Name,
    P.Category,
    OI.Quantity,
    OI.Price AS Item_Price,
    (OI.Quantity * OI.Price) AS Item_Total,
    O.Status AS Order_Status
FROM ORDER_ITEM OI
JOIN ORDERS O    ON OI.Order_ID = O.Order_ID
JOIN CUSTOMER C  ON O.Customer_ID = C.Customer_ID
JOIN PRODUCT P   ON OI.Product_ID = P.Product_ID
ORDER BY O.Order_ID, OI.Order_Item_ID;
Academic DBMS Project

E-Commerce Order Management System

A comprehensive relational database dashboard engineered to manage customers, catalog products, purchase orders, and item line transactions with strict referential integrity.

DBMS Course Project
Relational Data Model (3NF)
MySQL / SQL Schema

Project Objective

To design, develop, and demonstrate a robust relational database management system for an e-commerce enterprise. The system handles:

  • Customer Record Management: Storing unique customer identities, contact numbers, email addresses, and residential shipping addresses.
  • Inventory & Product Catalog: Tracking product specifications, categorized listings, unit prices, and warehouse stock units.
  • Order Processing Lifecycle: Generating orders linked to customers with timestamped dates, computed total invoice values, and dynamic status tracking (Pending, Processing, Shipped, Delivered, Cancelled).
  • Order Item Normalization: Resolving the Many-to-Many (M:N) relationship between Orders and Products via a dedicated associative table with line-item pricing and quantities.

Technologies Used

SQL / MySQL

Relational schema design, Primary/Foreign Key constraints, normalization (1NF, 2NF, 3NF), and query execution.

HTML5

Semantic markup, modal dialogues, responsive layout containers, and accessible UI controls.

CSS3

CSS Custom Properties, Glassmorphism, Flexbox, CSS Grid, Dark/Light mode theme system, and smooth transitions.

Vanilla JavaScript (ES6+)

Client-side LocalStorage database engine, relational integrity checking, interactive SQL runner, and Chart.js integration.
